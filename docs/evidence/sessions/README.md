# 会话导出与事件清单（缺口声明）

## 现状

本目录**没有**会话 Markdown 与 JSON/JSONL 事件清单。原因是平台会话未导出，事后无法重建原始消息顺序、工具调用与失败重试；按检查规则，此类内容不得补造。

替代材料（可核对，但不能替代原始会话）：

| 材料 | 能证明什么 | 不能证明什么 |
|---|---|---|
| `docs/requirements.md` | 需求理解与验收条件 | 当时的提示词内容与顺序 |
| `docs/tasks.md` | 任务拆分与依赖 | 任务是否按此顺序执行 |
| `docs/ai-usage.md` | AI/学生分工与四例纠错 | 纠错发生在哪条消息 |
| `docs/evidence/test/*` | 测试与覆盖率的真实输出 | 执行这些命令的会话上下文 |
| `docs/evidence/T10/*.log` | 场景演练的真实结果 | 演练时学生对 AI 输出的判断过程 |
| `docs/evidence/skills/*` | Skill 的结构、用途与结论 | Skill 被触发的原始调用记录 |

## 导出清单（补齐时按此执行）

1. 按阶段导出：准备 / 需求 / 原型 / 规划 / 开发 / 测试 / 验收 / 部署 / 总结，每阶段一个 `NN-阶段名.md`。
2. 每份文件顶部写：工具与模型版本（不可获取字段标注"不可获取"）、时间段（北京时间）、关联提交哈希。
3. 原文保留学生输入、AI 可见回复、工具调用与输出、失败重试；附件用相对路径索引到 `docs/` 或 `docs/evidence/`。
4. 另出 `events.jsonl`：每行 `{"ts","stage","role","action","tool","result","version"}`，按时间升序。
5. 脱敏：删除 Token、口令、连接串、个人手机号；不得改变时间与顺序。
6. 完成后在本文件补充"已导出范围 + 仍缺范围"，并更新 `docs/evidence/gaps.md` G-02、G-03。

## 影响

缺此项目会持续影响 B1-05、B1-06、B2-03、B2-04、B2-06、B2-07 六条原子项；补齐后可按检查报告第 6 节的复验条件申请复评。
