# AI 使用说明（题目 10）

> 整理日期 2026-11-12。本文档回答"各阶段 AI 做了什么、学生审核了什么、纠错在哪"。
> 局限：平台会话未导出为 Markdown/JSONL，本文引用的是仓库内可核对的产物与日志；会话级证据仍属缺失（见 `docs/evidence/gaps.md`）。

## 1. 分工总览

| 阶段 | AI 承担 | 学生承担 | 可核对产物 |
|---|---|---|---|
| 需求 | 按题面拆规则、列边界与验收条件 | 确认范围、记录假设（A-01~A-03）、否决"改规则/撤积分"类扩展 | `docs/requirements.md`、`docs/assumptions.md` |
| 原型 | 生成三端页面骨架与状态文案 | 决定页面只保留必要操作、不引入前端框架 | `docs/prototype.md`、`internal/server/web/*.html` |
| 规划 | 拆任务与依赖 | 调整优先级：先保证事务与幂等，再补页面 | `docs/tasks.md` |
| 开发 | 写迁移、store、service、handler、页面 | 审核事务边界与状态码；要求补唯一键兜底 | `migrations/*`、`internal/**` |
| 测试 | 写用例、跑 `-race`、算覆盖率 | 判定"并行失败"是基建问题而非业务问题；要求按包隔离库 | `internal/**/*_test.go` |
| 验收 | 对照题面逐项核查 | 接受第三方验收报告结论，逐条整改 | `docs/evidence/acceptance/*` |
| 部署 | 写 Dockerfile/compose/CI/初始化脚本 | 实机执行部署、观察乱码并定位字符集 | `Dockerfile`、`docker-compose.yml`、`.github/workflows/ci.yml` |

## 2. 学生实际审核并纠正的四例

| 编号 | AI 初稿的问题 | 学生的判断 | 纠正结果 |
|---|---|---|---|
| R-01 | 用 `count == 门槛` 判定发奖 | 历史缺口与跳档会漏发，应"达到及以上都尝试，重复由唯一键兜底" | 改 `>=`，新增 `TestEvent_RewardWhenCountAboveThreshold` |
| R-02 | 测试库固定名、需要 `-p 1` 才稳定 | 并行随机失败说明基建有问题，不能靠串行掩盖 | 按包派生库名，`go test ./...` 并行 -race 全绿 |
| R-03 | 发奖、流水、余额分三次写 | 必须同事务，否则"余额≠流水" | 收敛为单事务，余额与流水强一致 |
| R-04 | 直接在主分支改代码 | 必须在 `dev/10` 开发，PR 合并后再部署 | 已在 `dev/10` 工作；提交与 PR 仍待执行 |

## 3. 不采纳的 AI 建议

| 建议 | 不采纳原因 |
|---|---|
| 引入 Gin/ORM 之外的依赖与前端构建链 | 题面只要求最小可操作页面，增加依赖无收益 |
| 用 Redis 做发奖幂等 | 单库唯一键已满足，多组件不参与评分且增加故障面 |
| 用静态 HTML 假数据"演示"异常分支 | 题面禁止用静态页面代替真实分支 |
| 为覆盖率达标而排除 handler/store | 题面明确禁止排除自编 DAO/HTTP 代码 |
