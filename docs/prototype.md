# 原型与页面状态说明（题目 10）

> 事后整理版（2026-11-12）。页面为纯 HTML + fetch，无构建步骤，由 `internal/server/web` 与 `internal/readingsvc/web` 通过 `embed` 打包。
> 说明：本文档描述的是**已实现页面的交互契约**；原型阶段文件未单独留档，此点已在检查报告中列为历史缺口，不用本文档冒充原型当时的产物。

## 1. 页面清单

| 页面 | 路径 | 服务 | 角色 | 主要接口 |
|---|---|---|---|---|
| 入口导航 | `/` | app :8080 | 全部 | 无（仅跳转卡片） |
| 用户端 | `/user` | app | 用户 | `GET /api/v1/users/activity`、`/progress?date=`、`/points`、`POST /appeals` |
| 运营端 | `/ops` | app | 运营 | `POST /api/v1/ops/activity`、`GET /api/v1/ops/summary?date=` |
| 客服端 | `/agent` | app | 客服 | `GET /api/v1/agent/appeals?status=`、`/appeals/:id`、`POST /appeals/:id/reject`、`/appeals/:id/compensate` |
| 模拟阅读服务 | `/` | readingsvc :8081 | 模拟上游 | `POST /api/v1/events`（带 `X-Source-Token`）、`GET /api/v1/records` |

身份切换：三端页面顶部下拉选择预置账号令牌（`user-token-1..5`、`agent-token-1`、`ops-token-1`），所有请求以 `Authorization: Bearer <token>` 发出，后端按令牌解析角色与用户，**不接受请求体里的 user_id 作为身份**。

## 2. 用户端 `/user`

| 区域 | 输入 | 正常状态 | 异常状态 |
|---|---|---|---|
| 活动信息 | — | 活动名、起止时间、门槛、积分、当前业务时间 | 无活动：提示"暂无已发布活动"，不报错 |
| 每日进度 | 日期选择 | 已读文章数/门槛、是否达标、是否已发奖、文章列表 | 未读：0/3 且列表为空；日期无活动：门槛 0 |
| 积分与流水 | 刷新 | 余额 + 流水列表（类型/分值/关联 reward） | 无流水：余额 0、列表为空 |
| 提交申诉 | 日期 + 描述 | 提交成功返回申诉 ID，状态"待处理" | 已有未结申诉：提示"已有待处理申诉"；描述为空：400 |

## 3. 运营端 `/ops`

| 区域 | 输入 | 正常状态 | 异常状态 |
|---|---|---|---|
| 发布活动 | 名称、开始、结束、门槛、积分 | 返回活动 ID 与"已发布" | 重复发布：409「活动已发布」；结束时间早于当前：400；参数非法：400 |
| 发布后规则 | — | 只读展示，无修改控件 | 无入口（符合题面"发布后固定"） |
| 某日汇总 | 日期 | 达标人数、发奖人数、积分总额、申诉结果、`window_closed`、不一致明细 | 窗口未关闭：`window_closed=false` 并提示"仍有迟到窗口"；存在脏数据：`inconsistencies` 列出 user_id 与原因 |

## 4. 客服端 `/agent`

| 区域 | 输入 | 正常状态 | 异常状态 |
|---|---|---|---|
| 申诉列表 | 状态筛选 | 列出 ID/用户/业务日/内容/状态 | 空列表：显示"暂无申诉" |
| 核查详情 | 申诉 ID | 已接收事件、本地进度、是否已发奖、可信记录、`trusted_note` | 可信查询失败：`trusted_note` 写明失败原因，核查仍可继续；申诉不存在：404 |
| 驳回 | 依据文本（必填） | 状态→已驳回，记录依据与操作者 | 依据为空：400「驳回必须写明依据」；已处理：409 |
| 补入 | 事件编号、文章 ID、发生时间 | 走统一事件路径，达标即发奖并自动结案，返回 reward ID | 参数缺失：400；超窗/活动外：返回 `rejected` 及原因；已处理：409 |

## 5. 模拟阅读服务 `:8081`

| 区域 | 行为 |
|---|---|
| 上报事件 | 记录（event_id、user、article、occur_at，biz_date 按北京时间取日期），以固定 token 转发给主服务 `/api/v1/events` |
| 可信查询 | 按 user + 日期返回记录列表，供客服核查比对 |
| 失败注入 | 支持配置超时/错误响应，用于演示"可信查询失败降级为说明文字" |

## 6. 页面与规则的对应

- R1 → `/ops` 发布区（无修改控件）
- R2 → 事件仅由 readingsvc 携带 token 提交，页面不直连
- R3/R4 → `/user` 进度区展示去重后文章数与"已发奖"标记
- R5 → `/user` 只显示当前令牌用户数据
- R6/R7 → `/agent` 详情区并列展示"已接收事件 / 本地进度 / 可信记录"三份证据
- R8 → `/ops` 汇总区（含 `window_closed` 与不一致明细）
