# 题目 10 逐项验收（验收检查）

## 用途

以原始题面为唯一依据，对指定代码版本逐项验证并出具验收报告。供验收 Agent 在**独立会话**中使用，不采信开发/测试 Agent 的完成声明。

## 触发场景

- 测试通过、发起 PR 之前（预验收）。
- PR 合并前门禁（正式验收）。
- 验收后业务代码有变更，需重新验收受影响条款。

## 输入

- 原始题面文件（题目 10 全文 + 题集第一部分通用要求）。
- 待验收版本代码（记录提交哈希）。
- 测试报告、覆盖率原始文件（`coverage.out`）、部署记录、Skill 使用记录的位置。

## 执行步骤

1. 读取 `references/acceptance-checklist.md`，取得完整验收条款清单。
2. **逐条规则核对**（题目 10 规则 1~8）：每条给出 通过/不通过 + 证据位置（文件:行号、接口响应、页面操作或数据查询结果索引）。
3. **五个必演场景**：正常活动 / 重复与延迟 / 申诉成立 / 申诉不成立 / 并发与收尾——逐一确认可实际操作且有持久化结果；静态页面、写死结果、仅文档说明均判不通过。
4. **质量证据**：总覆盖率 ≥85% 且核心业务包分别 ≥85%；并发验证可重复且含 `-race`；测试命令原始输出在案。
5. **Git 与流程证据**：提交符合 `[类型] [版本] [#编号] 描述` 格式且 feat/fix 编号经 meegle 核验留痕；业务代码均在 `dev/10`；验收版本与 PR/部署版本哈希对应。
6. **红线检查**：客服未直接改余额或原始事件；发奖同事务；越权访问被拒；无密钥/敏感信息入库入档。
7. 汇总输出验收报告并归档。

## 输出格式

```text
验收版本：<提交哈希>
逐项结论表：[题面条款] → 通过/不通过 → 证据位置
必演场景覆盖表：场景 → 演示证据位置
不通过项汇总：条款、缺口、需补充内容
最终结论：通过 / 不通过
```

## 失败处理

- 任一"通过"缺少可核查证据 → 该项按不通过处理。
- 发现不通过项 → 输出缺陷清单交回开发；修复后仅对受影响条款复验，并记录复验对应版本。
- 验收后业务代码变更 → 全部结论作废，对新版本重新验收。

## 完成标准

清单条款 100% 有结论、有证据；不通过项全部闭环或明确列入整改清单；报告归档至 `docs/evidence/acceptance/`。
